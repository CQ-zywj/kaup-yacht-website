公司资料保存同步 accounts 和 supplier_profile；密码摘要不会进入商品供应商副本，也不会在公司编辑时被覆盖。商品公开读取关联当前公司信息。已注册供应商的草稿按 supplier_id 区分，不能用另一个供应商账号编辑；旧未绑定资料的草稿可继续补填。

保存草稿仅改 draft_products：浏览器将城市改为 “Draft only city” 后保存草稿，刷新仍显示该值，而公司页仍显示 Dalian。之后在公司页保存 Qingdao，再编辑同一草稿优先使用更新后的 Qingdao。通过公司 profile_revision 区分未提交草稿编辑与公司资料更新，避免旧副本回滚企业信息。

## 自动化与修复证据

执行 `node --test tests/*.test.cjs`：最终 36 项通过、0 失败。新增覆盖供应商必填/邮箱/官网、注册协议与密码、跨账号资料隔离、损坏资料类型、保存失败回滚、登录字段保留、草稿资料版本、来源 URL 参数合并及多选组错误定位。所有 JS 语法检查通过。

以下问题均复现后加入失败测试，再修复至通过：

- 多选主营类目返回 RadioNodeList，原错误函数对 classList 的调用导致异常；现在分别标记组内控件。
- 带查询参数的登录来源再次添加问号，导致商品上下文损坏；现在合并原 query。
- 公司资料保存将副本中的 undefined password_hash 写入账号，导致再次登录失败；现在资料和登录字段分离，浏览器重新验证公司更新后可登录。
- 多键写入失败可能导致账号和资料不一致；补充回滚测试。
- 旧草稿副本覆盖最新企业资料、切换供应商写入另一企业资料；补充归属和版本检查。
- 可解析但类型错误的资料对象导致页面渲染异常；增加消费字段校验，损坏数据保留并提示。

按 requesting-code-review 技能完成一次独立只读审查，确认的资料归属问题、顶部公司名同步和资料类型校验问题均已处理。未把该次审查宣称为修复后再次独立复审。

## 实际边界

全部账户、审核、文件和提交为本地演示，没有接入后端或发送邮件。静态身份限制不能提供生产安全隔离；后端仍须鉴权。头像为占位，证书和实拍保存文件名而非真实上传文件。Google/LinkedIn、记住我、忘记密码、个人中心、收藏和采购历史为 PRD 指定的占位或说明。

仅验证本地 HTTP；测试浏览器禁止 file 协议，直接双击没有新增运行验证。跨浏览器和真实存储配额耗尽未实测，异常存储由单元测试验证。测试只使用假企业、假联系方式和项目自带图片，没有清空用户原数据。测试中较早创建、因已修复错误而失去摘要的自建测试账号不作为交付演示账号；内置 demo-buyer/demo-supplier 可用指定演示凭据登录。
