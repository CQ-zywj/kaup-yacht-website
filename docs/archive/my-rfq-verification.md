# 2026-10-09 买家我的询盘验收

范围：依据《PRD-出海平台第一梯队优化_副本.md》v0.3，仅补齐买家询盘跟踪。

## 实现

新增 my-rfq.html 与 js/my-rfq.js。只读现有 rfq_drafts，按 buyer.id 与当前登录买家 id 严格匹配，无 buyer.id 旧记录不展示、不迁移。数据契约和供应商状态机保持原样。

买家主导航、账户菜单、页脚及提交成功弹窗接入“我的询盘”。列表支持全部/已发送/已查看/已回复和最新/最早排序。详情含商品或通用采购上下文、类目、数量、旧目标市场、交期、贸易条款、说明、附件元数据及供应商回复。缺失字段显示“—”，未回复显示等待提示。

未登录、非买家和登录失效引导买家登录，返回当前页面。读取失败显示存储错误和重试入口。列表及打开的抽屉响应 storage、重新聚焦及语言切换。

## 验证证据

- 新增单元测试先失败再通过：买家严格隔离、排除旧记录、角色检查、状态筛选、时间排序、原数据不变及缺失可选字段兼容。
- 演示买家提交 3 艘 p01 游艇采购，成功弹窗同时显示“查看我的询盘”和“返回产品列表”；另一个已打开买家标签页立即显示新增记录及已发送状态。
- 买家打开详情前后 rfq_drafts 原始字符串完全一致，未标记已查看或改写数据。
- 供应商实际打开收件箱并回复，原买家重新登录后看到已回复状态、报价、回复时间。
- 在测试询盘临时更新回复，已打开的另一个标签页详情立即刷新；同步测试后精确恢复原回复。
- 另一买家账号显示 0 条和空状态，不能看到演示买家的 2 条记录。无 buyer.id 的旧询盘仍在供应商端，买家列表不展示。
- 供应商访问及未登录访问均引导买家登录，成功登录返回 my-rfq.html 且语言参数保留。
- 筛选无结果、最早排序、中英文状态和详情正常。列表与抽屉在 375、768、1280 宽度均无横向溢出。
- 仅在测试标签页临时模拟 localStorage 访问失败，出现存储错误/重试提示；重新加载恢复，未修改存储数据。
- Node 测试 43 项通过，脚本语法与 git diff --check 通过。

## 静态原型边界

所有标签页共用 localStorage 登录态，不能同时保持两个不同身份；角色切换会刷新相关页面。这一行为不影响同源询盘记录共享。登录、询盘及回复均为本地演示，附件不上传、不提供真实下载。
