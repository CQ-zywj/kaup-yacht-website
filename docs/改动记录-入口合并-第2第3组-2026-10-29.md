# 改动记录：入口收敛第 2、3 组（2026-10-29）

对应 `docs/入口收敛方案-2026-10-29.md` 第 2 组（两个对外主页）与第 3 组（新建商品）。两组都是"少一个入口"，不删页面能力。

## 一、第 2 组：公司主页并入店铺主页

### 问题

`storefront.html` 与 `company-public.html` 都吃 `?supplier_id=`，都展示简介 / 证书 / 团队。后者是前者的严格子集——`js/company-public.js` 页面顶部自己还放了一个"去店铺主页"的链接，等于承认自己重复。

后果：一个供应商对外有两个主页地址，排版不同、内容交叉。买家会怀疑哪个才是官方页面，对外投放也会互相稀释。

### 改动

| 位置 | 改动 |
| --- | --- |
| `company-public.html` | 整页改为 302 跳转：带 `supplier_id` → `storefront.html?supplier_id=…&lang=…`；不带 → `suppliers.html`（没有主体的公开页没有意义）。保留文件，已发出或收藏的旧链接不会 404 |
| `js/company-public.js` | 清空为说明性注释，不再被执行。原逻辑（`publicProfile()` 白名单 + `publicCertificates()` + 团队）在 `storefront.js` 里是同一套 |
| `js/storefront.js` | ① 删掉头部指向 `company-public.html` 的「公司信息」按钮（店铺页自己就包含这些内容，按钮是自我跳转）；② 简介段落加 `preserve-lines`，继承原公司主页的多行排版 |
| `assets/styles.css` | 删除随之失效的 `.company-public-logo`（100×100 徽标样式） |

**关于 `js/company-public.js` 为什么不删文件**：仓库没有版本控制，删除不可逆；文件只有 15 行，留一份带说明的空壳，比彻底消失更容易追溯"这个页面去哪了"。

## 二、第 3 组：批量导入降为发布页内入口

### 问题

侧栏里「发布商品」和「批量导入」并列成两个一级项。但"新建商品"是一个任务，"单件填"和"表格导"只是两种方式——方式不该和任务平级，否则用户每次都要先判断"我该点哪个"。

### 改动

| 位置 | 改动 |
| --- | --- |
| `js/supplier-shell.js` | 「商品」组去掉「批量导入」子项，收敛为 2 项（我的商品、发布商品）；新增 `GROUP_ALIAS`，让批量导入页仍能展开「商品」组但不高亮任何子项 |
| `js/publish.js` | 页头加一行引导：`多个商品一次录入？用表格或产品资料导入。批量导入 ↗` |
| `js/bulk-import.js` | 页头加「← 返回发布商品」，与「我的商品」并排 |
| `js/bulk-i18n.js` | 新增 `backToPublish`、`bulkFromPublishHint` 两键 |
| `assets/supplier-ui.css` | 新增 `.bulk-head-links`（返回链接 + 我的商品的横向容器） |

侧栏业务页从 12 项减为 11 项，页面总数仍是 27（`bulk-import.html` 没删，`tests/static.test.cjs` 的页面清单也没动）。

### 没有按方案做的一条

方案第 3 组写着"`bulk-import.html` 的「资料包」模式从界面下线（代码保留，加 hidden 开关）"。**本轮没做**，原因：

- 资料包模式是 `bulk-import.html` 页内的第二个 tab，不是侧栏里的并列入口。方案要解决的是"一级入口并列"，页内 tab 不在这个问题里。
- 它是已实现的可用能力（DOCX + 图片成组导入），下线属于削功能，不是入口收敛。要下线应该单独判断价值，不该混在导航调整里一起做。

需要的话可以单独一轮处理。

## 四、排查中确认的一件事

`accounts` 与 `supplier_profile` 是两份数据，`MarineAccounts.writeProfile()` 会同步两者；直接 `localStorage.setItem('supplier_profile', …)` 只改一份。店铺页 `resolve()` 优先读 `accounts`，所以在测试里绕过 `writeProfile` 写数据，会看到"改了却没生效"。这不是页面缺陷，但说明**任何数据修复/迁移脚本都必须走 `writeProfile`**。
