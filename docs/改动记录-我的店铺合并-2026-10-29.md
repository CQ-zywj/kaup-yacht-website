# 改动记录：「我的店铺」合并（2026-10-29）

方案见 `docs/入口收敛-我的店铺合并方案-2026-10-29.md`。本文记录实际改了什么、为什么这么改、怎么验证的、还剩什么。

## 一、要解决的问题

改之前，同一批店铺门面信息有两套入口、两套字段、两次保存：

| 字段 | 公司资料页（company.html） | 店铺装修页（store-decoration.html） |
| --- | --- | --- |
| logo | 有（`logo_file`） | 有（`logo`） |
| 横幅 | 无 | 有（`banner` / `banner_files`） |
| 标语 | 有（只读展示） | 有（可编辑） |
| 主题 | 有（只读展示） | 有（可编辑） |

结果是：供应商要先在装修页调门面，再回公司页填资料，两边都保存一次才算完；`logo` 与 `logo_file`、`banner` 与 `banner_files` 两套字段还会互相盖掉。侧栏 13 项里还并排放着「我的店铺」（旧名 company）和「店铺装修」，用户分不清该进哪个。

改成一句话：**编辑公司信息时，顺手把店铺门面填完。**

## 二、改后结构

`company.html` 一个入口，五个分区，右侧常驻预览：

```
我的店铺
├─ 企业信息   company-basic        公司名、国家、城市、地址、业务类型、规模、联系人与简介
├─ 店铺门面   company-shopfront    标语、主题、logo、横幅（≤3）、店铺视频
├─ 团队成员   company-team         成员头像、姓名、职位
├─ 实拍图片   company-photos-panel 工厂/产品实拍
└─ 认证资质   company-certs        证书入口（跳 certifications.html）

右侧：shop-preview-card（sticky，随输入实时更新）
```

左侧改、右侧看，保存前就知道店铺页长什么样——这是把两个页面合并后能给出的、原来做不到的东西。

## 三、逐文件改动

### `js/company.js`（核心）

- `companyEditFields` 白名单补 `banner_files`。**这是修复 bug**：原来横幅的 Blob 引用不在草稿白名单里，草稿能恢复到编辑态但横幅丢失，用户会以为"传了没生效"。
- `storefrontEdit()` → `shopFrontSection(p)`，section id 改为 `company-shopfront`，内容改为标语 + 主题 + logo + 横幅 + 视频五组；移除指向 `store-decoration.html` 的链接和"先去装修页"的提示；`address` 移入 `company-basic`。
- 新增 `previewMarkup(p)` / `bindPreview(form)`：右侧预览卡，响应标语、主题、公司名、logo、横幅；本地文件用 `URL.createObjectURL` 预览，`pagehide` 时统一 revoke，避免泄漏。预览卡的无障碍标签只能用纯文本 `U.t()`——第一版误用了返回 HTML 片段的 `U.tr()`，把 `aria-label` 撑破，页面上多渲染出一行「店铺预览」（已修，并加了静态检查防回归）。
- `collectCompany()` 改为**先全部校验、再统一写盘**：标语长度、横幅张数、logo/横幅/团队三类文件一次校验完，全部通过后才 `SupplierFiles.putMany()`。任一项被拒时不会出现"logo 已入库、横幅被拒"的孤儿 Blob。
- `editMarkup()` 改为 `.shop-edit-layout > .shop-edit-main` 双栏结构；删除授权区块（本来就在认证页）。
- 页面标题 `companyProfile` → `myStore`。

### `js/supplier-files.js`

- 新增 `check(files, kind)`，`putMany()` 内部复用它。调用方可以先校验整张表单的文件再决定是否写盘。
- **修复本地库不自愈的问题**：原来 `indexedDB.open('northlink-supplier-files', 1)` 写死版本号，如果同名库已存在但缺 `files` / `finance` 表（首轮中断、早期版本残留、别的脚本先建了空库），`onupgradeneeded` 不再触发，之后所有上传都抛 `NotFoundError`，页面只能显示"存储异常"。现在打开后检测缺表，缺表则关闭连接、升一版补建。

### `js/supplier-settings.js`（整体重写）

- 删除 `finance ? 装修表单 : 财务表单` 的双分支，只保留银行资料表单。
- 保留原"先校验再写"的正确顺序；底部加「我的店铺」引导链接，避免用户找不到门面设置。

### `js/supplier-shell.js`

- 侧栏 `ITEMS`：`consoleCompany + company.html` 与 `consoleDecoration + store-decoration.html` 两项合并为 `myStore + company.html`，控制台侧栏 13 项 → 12 项。

### `store-decoration.html`（整体重写）

- 改为跳转页（`meta refresh` + `location.replace('company.html')`）。保留文件是刻意的：`tests/static.test.cjs` 的页面清单包含它，删文件会让测试失败，也会让收藏的书签 404。

### `assets/supplier-ui.css`

- 新增 `.shop-edit-layout`（`minmax(0,1fr) 272px` 双栏）、`.shop-preview`（sticky top 92px）、`.shop-preview-banner`（三套主题渐变）、`.shop-preview-logo`、`.shop-preview-text`；`@media (max-width:960px)` 时预览折叠为顶部条。

### `js/i18n.js`

- 新增 `myStore`（我的店铺 / My store）、`storePreview`（店铺预览 / Store preview）、`storePreviewHint`；`saveCompany` 文案改为「保存店铺资料 / Save store」。
- 删除 3 个因此失效的键：`companySaveFirst`（"请先保存公司基础资料"提示已移除）、`consoleDecoration`（侧栏项已合并）、`storefrontAddress`（地址行已从门面摘要移除）。键总数维持 916，中英成对校验 0 异常。

### 其余

- `company.html`：`<title>` 改为 `NORTHLINK | My store`。
- 全部 `*.html`：静态资源版本号 `?v=ws20261029b` → `ws20261029c`（360 处），避免浏览器继续用旧的 `supplier-files.js`。
