## 1. 为什么删

这两组不属于"入口重复"，审查报告把它们归在 **A6「首页演示采购线索是纯填充」** 和 **C4「死代码与演示分支」**：

| 对象 | 问题 |
| --- | --- |
| 首页 3 条演示线索 | 买家不存在，点"联系"只弹一句说明。平台卖的是"帮你找买家"，首页却摆着 3 条不存在的买家需求——**信任风险，不只是冗余** |
| `toPublicRfq()` | 注释声称"1440 分钟无人回复自动转公开"，实际无调度器、无调用方。危害是误导接手的人以为系统有这个兜底能力 |
| `seedDemo()` | 每次挂载控制台就自动写 4 证书 / 3 文章 / 5 素材 / 门面字段。没人同意就写用户数据，且写入的是无法解释的假营业执照 |

## 7. 代价与后续

- **演示成本上升**：想展示证书墙、文章列表、素材库、店铺认证区，需要手工建数据。这是本轮明确的取舍（用户选择"接受空状态"）。
- 若将来要恢复"一键演示"，正确做法是做一个**显式的导入**（上传一份 demo JSON 或"载入示例数据"按钮），而不是回到"进页面就偷偷写"。`SupplierCore` 的导入接口（`bulk-core.js` / `document-import.js`）已经具备承接能力。
- `inquiry-detail.html` 保留为跳转页而非删文件：`tests/static.test.cjs` 的页面清单仍按 27 页校验，老链接也不会 404。第 2 组（`company-public`）、第 1 组（`store-decoration`）是同样处理方式。
- `mock/editorial-data.js` 现在是 2 个数据集（news 3 条、exhibitions 2 条），仍是演示内容，但都属于"资讯"而非"商机"，不构成信任风险，本轮未动。
- `docs/研发交接-供应商端能力合并-2026-10-29` 的三种格式已同步：`.md` / `.html` / `.docx` 的存储键表里 `demo_supplier_seeded` 均加删除线并注明「已删除（2026-10-29 随 `seedDemo()` 移除）」；`store-decoration.html`、`company-public.html` 两行统一写成「~~旧描述~~ → 已并入 `company.html` / `storefront.html`，文件保留为跳转页」；截图清单剔除两个已下线页面的截图并补一句历史对照说明。`.docx` 因本机无 pandoc，是直接改 `word/document.xml` 后按原 zip 顺序重新打包的，已用 `textutil` 验证可正常解析。
