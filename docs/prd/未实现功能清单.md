## 3. 数据模型缺口（PRD §4）

| 数据键 / 字段 | PRD 要求 | 当前实现 | 缺口 |
| --- | --- | --- | --- |
| `draft_products.status` | `draft / pending / active / inactive / rejected` | 仅 `draft / published` | 缺 3 态及流转、买家列表按 `active` 过滤 |
| `rfq_drafts.supplier_id` | 必填 | 无 | 收件箱无法按供应商隔离 |
| `supplier_profile.banner/theme/tagline` | 店铺门面 | 无 | 店铺主页无视觉配置 |
| `supplier_profile.completeness` | 资料完善度 | 无 | 工作台账户得分无数据源 |
| `certifications` | 证书数组（type/name/no/issuer/valid_from/valid_to/ownership/status/product_ids） | **不存在**（仅商品内嵌 `certifications` 数组，结构不同） | M3 全部依赖它 |
| `articles` | 文章（title zh/en、content_html、cover、category、status、publish_at、supplier_id、sidebar_config） | **不存在** | M4 全部依赖它 |
| `blog_sidebar` | 侧边栏配置 | **不存在** | M4 侧栏 |
| `media_library` | 素材（id/type/folder/tags/url/name/supplier_id/created_at） | **不存在** | M5 全部依赖它 |

> 注意：现有商品对象里的 `certifications` 是**商品内嵌的证书行**（type/number/image），与 PRD 的全局 `certifications` 存储不是同一结构。M3 落地时需要明确"全局证书 → 关联商品 → 详情展示"的映射，不能直接复用。

## 6. 验收与风险提示

- **验收口径**：本清单每条的"验收要点"均取自 PRD 对应段落；建议逐条转成事项并指定负责人，验收时以"页面可操作 + 数据落 localStorage + 刷新不丢 + 中英可用 + 空状态友好"为最低标准。
- **本地存储上限**：素材库、证书原件、文章封面都会走 base64。浏览器 localStorage 通常 5MB，必须先决定"只存元数据/缩略图"还是"接后端"，否则演示到第三张证书就会写失败。
- **鉴权仍是模拟**：新增页面若涉及企业数据（证书、文章、素材），前端隐藏入口不等于权限隔离；正式上线必须由服务端校验 `supplier_id` 归属。
- **命名冲突**：PRD 的 §3.10 写 `content.html`，与现有公共资讯页冲突，需在开发前确认新文件名，避免覆盖已验收页面。
- **范围边界**：PRD 明确"运营后台/审核流本期不做"。本清单中的"模拟验真/模拟审核"仍属演示按钮，不要理解为已具备审核工作流。
