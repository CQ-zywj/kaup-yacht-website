## 0. 背景与目标

原型已完成商品发现、发布、询盘收发、买卖账号与公司资料（验收见 `docs/prd3-verification.md`）。本次仅聚焦**买家「我的询盘」视图**——买家提交询盘后无跟踪入口，`inbox.html` 又是供应商端（买家误入会被拦截），买卖双边闭环只有"买家发起 + 供应商回复"一半，买家视角缺失。

> 原第一梯队其余优化点（认证类型配置化、币种按字段渲染、发布分步 + 完成度）**不在本次范围**，本文档已移除相关内容。

**目标**：以最小改动补齐买家视角的询盘跟踪视图，保持现有数据结构和旧数据可读，为后续买家/卖家工作台、会话报价等第二、三梯队打好地基。

---

## 1. 背景与现状

- `PRD-前端静态原型-3天_副本.md` v0.4 §2.10 已**规划**"买家我的询盘"，但**代码未实现**（无对应页面/脚本）。
- `js/rfq.js`：提交成功弹窗引导 `products.html`（返回浏览），买家看不到自己的询盘。
- `js/inbox.js`：供应商收件箱，顶部 `requireSupplier()` 会拦截买家并显示"这是供应商工作台"。
- `rfq_drafts` 元素已含 `buyer.id`（`js/rfq.js` 写入 `id: rfqUser.id`）、`status`（submitted/viewed/replied）、`reply` 字段——买家侧视图所需数据**已具备**。
- 导航/账户菜单：`js/i18n.js` 已有 `buyerWorkspace`（买家采购）文案键，未接入。

## 2. 问题

1. 买家提交询盘后无跟踪入口，无法查看"已发送 / 已回复"状态与供应商回复内容。
2. 买家误入 `inbox.html` 被供应商拦截提示，体验断裂，且可能误以为平台无买家侧视图。
3. 买卖双边闭环只有"买家发起 + 供应商回复"一半，买家视角缺失。

---

## 3. 优化需求

**R1.1 新增 `my-rfq.html`（买家我的询盘）**
- 顶部标识"买家模式"；未登录买家访问时引导登录（复用 `authRequired` 模式），登录后返回原页面（`?return=` 合并 query，逻辑同 `js/rfq.js`）。
- **列表**：仅展示当前登录买家（`buyer.id === current_user.id`）的询盘条目：
  - 关联商品缩略图 + 中英标题（无商品关联显示"通用采购需求"）；
  - 数量、目标市场、提交时间；
  - 状态徽章：`submitted`=已发送 / `viewed`=已查看 / `replied`=已回复（中英）。
- **状态筛选**：全部 / 已发送 / 已查看 / 已回复；时间排序（最新/最早），前端内存处理（同 `inbox.js` 模式）。
- **详情抽屉**（复用 dialog drawer 样式）：完整询盘内容（商品上下文、数量、目标市场、交期、贸易条款、说明、附件元数据）+ 供应商回复区块（`reply.message`、回复附件元数据、回复时间）；未回复时显示"等待供应商回复"。
- **空状态**：暂无询盘，引导"去商品详情发起一条询盘"（链接 `products.html`）。

**R1.2 数据过滤规则**
- 列表只读 `rfq_drafts` 中 `buyer.id === 当前登录买家 id` 的记录。
- 旧数据中**无 `buyer.id`** 的询盘：不归属任何买家账号，在买家视图不展示（演示账号下不影响闭环演示）；如需演示，可在演示账号首次登录时以提示形式说明，不做数据迁移。
- 状态与回复与 `inbox.js` **同源同步**：供应商回复后，买家侧立即可见（同一浏览器 localStorage 共享；跨标签页用 `storage` 事件刷新，同 `inbox.js`）。

**R1.3 提交成功入口**
- `js/rfq.js` 提交成功弹窗：在"返回浏览商品"之外，增加"查看我的询盘"链接（`my-rfq.html`），引导买家进入跟踪视图。

**R1.4 导航与账户菜单入口**
- 买家登录后，主导航或账户菜单显示"我的询盘"入口（文案复用 `buyerWorkspace` 或新增 `myInquiries`）。
- 保持与供应商端 `inbox.html` 分开，避免角色混淆。

**R1.5 兼容性**
- `rfq_drafts` 旧记录（含 `buyer.id` 的）正常展示；字段缺失（如 `target_country`）显示 `—`。
- 未登录、登录失效、存储异常均有对应提示（复用现有 `authRequired` / `storageError` 模式）。

---

## 4. 数据契约

- 数据源：`localStorage.rfq_drafts`（**不变**，仅新增读取过滤逻辑）。
- 过滤键：`buyer.id === current_user.id`。
- 状态机：`submitted → viewed → replied`（沿用现有；买家侧 `viewed` 由供应商查看触发，买家侧展示时不做状态降级）。
- 新增文件：`my-rfq.html`、`js/my-rfq.js`。
- `js/i18n.js` 新增键：`myInquiries`（我的询盘）、`waitingReply`（等待供应商回复）、`yourInquiry`（我的询盘详情）等。

## 6. 验收标准

- [ ] 买家登录后提交一条询盘，可在"我的询盘"看到该条记录及"已发送"状态。
- [ ] 供应商在收件箱回复后，买家侧同源显示"已回复"与回复内容。
- [ ] 未登录访问 `my-rfq.html` 引导登录，登录后返回原页面。
- [ ] 状态筛选、时间排序、空状态、中英切换正常。
- [ ] 买家侧不显示其他账号的询盘；`inbox.html` 仍为供应商端（角色不混淆）。
- [ ] 全部新增/修改页面中英可用；买家端 375/768/1280 响应式无溢出；`node --test tests/*.test.cjs` 全通过。
