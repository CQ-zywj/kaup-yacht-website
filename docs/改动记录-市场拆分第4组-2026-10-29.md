## 1. 改之前：同一批需求有两处列表，市场对买家是个副本

第 4 组列出的是「询盘的四张列表」：

| 位置 | 角色 | 内容 |
| --- | --- | --- |
| `inbox.html` | 供应商 | 会话 + 报价 + 分配 + 指标 |
| `rfq-market.html` | 供应商 | 发现公开需求 + 「已报价」筛选 tab |
| `rfq-market.html` | 买家 | 「我的发布」列表 + 各家报价数 |
| `my-rfq.html` | 买家 | 全部线程（含公开需求主帖）+ 比价 |

`js/my-rfq.js` 的筛选条件是 `r.buyer?.id === user.id`，公开需求主帖本来就在里面——买家在两个页面看的是同一批需求的两个视角：市场页看"我发了哪些、有几家报价"，我的询盘看"哪条有新回复、要不要接受报价"。数量还对不上：市场页数的是主帖，我的询盘数的是全部相关线程。

供应商侧同理：「已报价」tab 是给"我报过的"再开一个列表，而"我报过的"在收件箱里本来就有完整会话（含买家回复），市场里那个列表只有报价金额，是个更弱的副本。

## 2. 结论：市场是供应商的页面，买家不需要

| 角色 | 问的问题 | 唯一答案 |
| --- | --- | --- |
| 买家 | 我的采购在哪 | `my-rfq.html` |
| 供应商 | 谁找我 | `inbox.html` |
| 供应商 | 有什么新机会 | `rfq-market.html` |

买家只要进「我的询盘」就能看到自己发布的全部询盘和收到的报价，市场对买家没有第二条信息——第一轮曾把买家视图改成"发布引导 + 计数 + 两个按钮"，仍然是一个只能转发链接的中间页；第二轮按用户判断直接去掉：**买家身份下不再有市场这一站**。

### 买家端

| 位置 | 处理 |
| --- | --- |
| 顶部导航 | 不再插入「RFQ 市场」项（`policy.role !== 'buyer'` 才插） |
| 页脚「买家采购」 | 去掉市场链接，只留 我的询盘 / 浏览产品 / 发布采购需求 |
| 页面内任何链接 | 全局规则 `filename === "rfq-market.html" → link.hidden = role === "buyer"`，一处兜住所有静态/动态入口 |
| 直接访问 `rfq-market.html` | `renderBuyer()` 改为 `location.replace(my-rfq.html)`，书签和老链接不落空、也不留一个只能看引导的页面 |
| 发布成功提示 | 原来主按钮跳市场（"去市场看看"），现在主按钮跳「我的询盘」、次按钮回「浏览产品」 |

买家发布需求的路径没有减少：`my-rfq.html` 工具栏右侧本来就有「发布采购需求 →」，落到 `rfq.html` 且无 `supplier_id` 时默认就是 **公开 RFQ** 模式（`js/rfq.js:49-54`），不需要额外参数。

### 供应商端

- 导航保留「RFQ 市场」一级项，列表就是"未关闭的主帖"，只保留搜索。
- 删除「已报价」筛选 tab：`const FILTERS`、`state.filter`、`.market-tabs` 容器一起移除，`state` 收敛为 `{ q: "" }`。
- 报价成功后不再 `state.filter = "mine"` 跳 tab，改为原地重渲染：卡片就地变 `is-quoted` 并显示报价金额，报价线程进收件箱。

> **与方案原文的一处偏差**：方案「验收」行写的是"供应商报价后该需求从市场'新机会'里消失"，但同一张表的「改造」行要求"卡片保留 `is-quoted` 标记与报价摘要（知道报过没）"。这两条不能同时成立——要让供应商知道"这个我报过"，它就得留在列表里。**取「改造」行**：留在列表、打标、显示报价金额，仅去掉"已报价"这个独立列表。如果产品上更希望"报过就消失"，把 `renderSupplier()` 里 `open` 的过滤条件加上 `&& !myQuoteOf(row.id, rows)` 即可，一处改动。

### 游客

保留：导航有「RFQ 市场」，点进去是"登录后使用 RFQ 市场"的双入口页（`renderGuest`）。市场是平台对外开放的能力展示，游客看不到需求内容，但知道有这回事。
