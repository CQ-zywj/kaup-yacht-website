# 船舶游艇 B2B 原型 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 PRD 六页静态原型并验证中英双语采购、发布、询盘及回复闭环。

**Architecture:** 使用普通 script 加载共享数据、字典、存储和页面脚本；无需构建工具，支持直接打开 HTML。业务筛选和状态更新为纯函数，DOM 渲染按页面分离，询盘统一使用 localStorage。

**Tech Stack:** HTML、CSS、原生 JavaScript、localStorage；Node 内置测试运行器用于业务函数测试，本地 HTTP 服务和浏览器用于交互验收。

**Spec:** ../../design.md

## Global Constraints

- 六个 P0 文件：index.html、products.html、product.html、publish.html、rfq.html、inbox.html。
- 不引入 React、Vite 或构建工具；不含后端、运营审核或真实邮件。
- 手写 16 件示例商品，每类 4 件，含至少 1 件缺少合规字段的涂装样例。
- 询盘初始不预置，使用 rfq_drafts；商品草稿使用 draft_products。
- 询盘状态为 submitted → viewed → replied，查看已回复询盘不降级。
- 全站中英包括导航、表单、筛选、枚举、错误、弹层、空状态和页脚。
- 买家端检查 375、768、1280；供应商端重点检查 1280，窄屏可操作。
- 本地媒体，普通 script，不依赖 fetch；提供本地 HTTP 演示方式。

## Review Focus

1. URL 含未知类目、无效数字或不存在的商品：稳定显示可恢复空状态，不崩溃。
2. localStorage 内容损坏或超配额：提示失败，禁止虚假保存成功。
3. 中英文切换发生在填写表单时：保留用户输入及商品上下文。
4. 涂装旧草稿缺合规项：可恢复编辑，但不能提交。
5. 已回复询盘再次打开及跨标签页新增：不降级状态，刷新收件箱数据。

## 文件职责

- assets/styles.css：设计变量、页面布局、响应式、焦点及错误样式。
- assets/media/：本地海事主视觉、产品示例媒体及占位图。
- mock/data.js、mock/categories.json、mock/products.json：内置类目模板及种子商品。
- js/i18n.js：集中中英字典和枚举映射。
- js/core.js：筛选、排序、合规校验、询盘状态纯函数。
- js/common.js：安全渲染、共享导航、语言、链接、存储、反馈弹层。
- js/home.js、js/products.js、js/product.js：买家发现页面。
- js/publish.js、js/rfq.js、js/inbox.js：供应商发布及询盘闭环。
- tests/core.test.cjs：业务规则测试。
- README.md、docs/verification.md：启动、演示、覆盖证据和限制。
