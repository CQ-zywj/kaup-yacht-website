## 0. 结论

上一版（2026-10-21）列出的 11 项缺口——工作台、店铺主页、认证资质、内容中心、素材库、发布增强、询盘归属、公司资料增强、详情验真、首页增强、客户管理——**在 2026-10-21 至 10-29 期间已全部实现**，其中询盘归属还进一步演化成「多轮线程 + 结构化报价 + 公开 RFQ 市场」。

所以这份文档的性质变了：**它不再是「补 PRD 的坑」，而是「从原型走向可上线产品还缺什么」**。剩下的缺口全部集中在服务端能力与交易闭环上，前端能做的增补已经不多。

剩下的 18 项按优先级分三档：

| 档位 | 数量 | 性质 | 不做的后果 |
| --- | --- | --- | --- |
| P0 | 5 | 没有就无法上线 | 数据会丢、权限可绕、无法真实成交 |
| P1 | 7 | 有才具备竞争力 | 能演示但不能运营，客户会觉得「缺东西」 |
| P2 | 6 | 体验与工程债 | 规模一上来就卡 |

## 2. P0 · 没有就无法上线（5 项）

### P0-1 服务端与数据持久化

| 项 | 内容 |
| --- | --- |
| 现状 | 数据 100% 在浏览器：`localStorage` 13 个键 + IndexedDB 2 个 store。换浏览器、清缓存、换设备即全部丢失 |
| 缺什么 | 关系库 + 统一数据访问层；前端 `U.read/U.write`、`MarineAccounts.*`、`SupplierCore.*`、`CustomerCore.*` 改为异步 API |
| 关键约束 | 现有校验规则（`js/core.js`、`js/supplier-core.js`）是纯函数、不依赖 DOM，应原样搬到服务端复用，避免前后端双实现漂移 |
| 验收 | 两台设备登录同一账号看到同一份数据；断网重连不丢草稿 |
| 覆盖期数 | 后端规划 P0 |

### P0-2 真实鉴权与会话

| 项 | 内容 |
| --- | --- |
| 现状 | `current_user` 是 localStorage 里的明文对象，可直接改成任意角色；密码为无盐 SHA-256 |
| 缺什么 | 注册/登录/刷新令牌、HttpOnly Cookie、密码改 Argon2id、角色与资源归属在服务端强制校验 |
| 特别说明 | 前端隐藏入口不等于权限隔离。当前所有「仅供应商」页只是渲染拦截，直接构造请求仍可读他人数据 |
| 验收 | 篡改前端存储无法提权；越权访问他人客户/证书/财务返回 403 |
| 覆盖期数 | 后端规划 P0 |

### P0-3 文件服务

| 项 | 内容 |
| --- | --- |
| 现状 | Blob 存 IndexedDB，页面只留引用；上传前做 MIME/体积/尺寸/SVG 安全校验 |
| 缺什么 | 对象存储 + 预签名上传 + 元数据表；服务端复检尺寸与类型（用 sharp 等，不信任前端）；清理 EXIF；病毒扫描 |
| 验收 | 上传 20MB PDF 不阻塞页面；同一文件重复上传可识别；恶意 SVG 在服务端也被拒 |
| 覆盖期数 | 后端规划 P0 |

### P0-4 交易闭环：订单 / 合同 / 支付 / 物流

| 项 | 内容 |
| --- | --- |
| 现状 | 止于「接受报价」。接受后会话转入中选子线程，但没有订单、合同、定金、物流任何环节 |
| 缺什么 | 报价 → 订单草稿 → 双方确认 → 合同/形式发票（PI）→ 定金与尾款 → 生产节点 → 出运与单据 |
| 建议范围 | 第一期只做「订单意向 + 形式发票生成 + 状态流转」，支付与物流对接放第二期 |
| 验收 | 从接受报价可一键生成 PI；双方能看到订单状态与节点时间；金额与报价一致可追溯 |
| 覆盖期数 | 后端规划 P2 |

### P0-5 机审服务端化

| 项 | 内容 |
| --- | --- |
| 现状 | `js/review-rules.js` 在前端同步判定，规则与词库都在客户端，改一处 `disabled` 即可绕过 |
| 缺什么 | 规则服务：同一份规则在服务端执行；提交后异步复核，前端判定只作即时反馈 |
| 关键约束 | 规则编号（P01/P03/C01…）必须保持稳定，驳回码与文案前后端共用 |
| 验收 | 前端被篡改仍能驳回；同一商品前后端判定结果一致；规则阈值可配置不发版 |
| 覆盖期数 | 后端规划 P0（接口）/ P1（全量规则） |

## 3. P1 · 有才具备竞争力（7 项）

### P1-1 邮件与站内信通知

现状：报价与回复后只弹「已邮件通知」文案，不实际发信；双方靠主动刷新。
缺什么：模板化邮件（新询盘、新报价、报价被接受、证书到期、账号审核结果）、站内消息中心、退订与频控。
验收：买家提交询盘后 1 分钟内供应商收到邮件；邮件内链接可直接进入对应线程。

### P1-2 企业实名与工商核验

现状：S01 的统一社会信用代码校验位算法已写好，但表单没有 `uscc` 字段；S02/S04–S08 全部待接。
缺什么：表单补 USCC 与营业执照结构化字段；对接工商接口做存续状态、经营范围、法人一致性核验。
验收：伪造 USCC 被拒；注销企业无法入驻；核验结果可在审核台查看。

### P1-3 证书与图片 OCR / 验真

现状：证书只有表单层校验（有效期、编号格式、CE 类别、分类强制私密）。
缺什么：证书 OCR 抽取编号与有效期并与填写值比对；图片水印与联系方式识别（P12/P13/M04）；图片分辨率检测（P10/M05）。
验收：上传他人证书图片可被识别；OCR 与手填不一致时挂起待人工复核。

### P1-4 平台运营后台

现状：无企业审核台、商品人工复核、举报处理、类目与规则配置、客服工单。
缺什么：审核队列（企业/商品/证书）、举报与下架、规则阈值配置、类目与参数模板管理、操作审计日志。
验收：审核动作有日志、可回溯；下架商品对买家立即不可见；规则调整不需要发版。

### P1-5 多币种与汇率

现状：币种固定 USD，价格符号写死 `$`，17 处硬编码。
缺什么：报价与商品支持多币种，展示按汇率折算，成交以报价币种为准并留汇率快照。
验收：EUR 报价在买家侧按当日汇率折算展示，PI 上显示原始币种与汇率。

### P1-6 买家工作台扩展

现状：买家只有「我的询盘」（含比价与成交）。
缺什么：收藏夹（店铺已能收藏，缺商品收藏与列表）、商品对比（当前只能比报价）、消息中心、采购历史与常用收货信息。
验收：收藏与对比跨设备同步；对比页可并排看 2–4 件商品参数。

### P1-7 搜索与推荐服务

现状：筛选与排序在前端内存里算，16 件商品够用，数据量上千会卡。
缺什么：全文检索（标题/描述/参数）、同义词与拼写容错、类目与关键词的搜索建议、相关推荐。
验收：1 万件商品下列表首屏 <1s；搜索「yacht」能命中「游艇」相关结果。

## 4. P2 · 体验与工程债（6 项）

| 编号 | 项 | 现状 | 要做什么 |
| --- | --- | --- | --- |
| P2-1 | 客户列表分页 | 一次渲染全部客户卡片 | 单供应商客户数上千时分页或虚拟滚动 |
| P2-2 | 文件去重与清理 | 同一文件多次上传存多份；对象 URL 只缓存在内存 | 内容指纹去重、孤儿文件回收、URL 生命周期管理 |
| P2-3 | DOCX 内嵌图片落库 | 导入时是 data URL，未写 IndexedDB | 导入时转存为文件引用再替换 src |
| P2-4 | XLSX 多工作表 | 只取当前选中工作表 | 支持多表合并导入与表间去重 |
| P2-5 | 数据统计与埋点 | KPI 为演示值，无曝光/访客/转化 | 埋点 + 统计接口；演示态与真实态要能区分 |
| P2-6 | 深色模式与旧浏览器 | 均不支持 | 按品牌需要评估；旧浏览器维持提示降级 |
