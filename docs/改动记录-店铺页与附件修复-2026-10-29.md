# 改动记录：店铺页重复询盘入口 + 附件可移除（2026-10-29）

两条来自实际使用的反馈，都是"能操作但体验不对"的问题。

## 一、店铺页出现两个「发起询盘」

### 现象

买家进 `storefront.html`，头部一个橙色「发起询盘」主按钮，右侧「联系与询盘」白卡片里又来一个「发起询盘」。同一屏两个入口指向同一个动作，用户要先判断"这两个有区别吗"。

### 判断

头部按钮是主 CTA（和「收藏店铺」成组，位置显眼），卡片里那个是重复。卡片本身只写了"通过平台询盘联系供应商"＋一个按钮，信息量不足以撑起一张独立卡片。

### 改动

| 位置 | 改动 |
| --- | --- |
| `js/storefront.js` | 删除整个 `.storefront-contact` 卡片（标题、说明文案、按钮、`config.contact_note`）；顺带删掉只为它存在的 `const config = {}` |
| `assets/styles.css` | `.storefront-about` 由两列改为单列（否则右侧留一块空白）；删除随卡片失效的 `.storefront-contact dl/dt/dd` 三条规则 |
| `js/i18n.js` | 删除失效键 `storefrontContact`（联系与询盘）、`contactViaPlatform`（通过平台询盘联系供应商） |

联系入口现在只有头部一个按钮，与「收藏店铺」并排。

## 二、附件选完不能删

### 现象

询盘表单里选好附件，列出来了，但每个条目只能看不能改。选错文件只能刷新页面重填整张表。

### 改动

| 位置 | 改动 |
| --- | --- |
| `js/common.js` | `filesHtml(items)` 增加第二参数 `removable`：为 `true` 时每条带一个 `×` 按钮（`data-remove-file` 索引 + `aria-label`）。只读场景（消息里的历史附件、我的询盘）不传该参数，行为不变 |
| `js/rfq.js` | 附件改为同时保留 `File[]`（`picked`）与元数据（`files`）。删除时 `splice` 后重绘，并用 `DataTransfer` 重建 `input.files` |
| `js/inbox.js` | 收件箱回复附件同样处理（同一类死路，一起修） |
| `assets/styles.css` | `.file-item.removable` 右内距 46px，`.file-remove` 圆形按钮绝对定位在右上角，hover 变红 |
| `js/i18n.js` | 新增 `removeAttachment`（移除附件 / Remove attachment） |

### 为什么要重建 `input.files`

只从数组里删掉元数据是不够的：`<input type="file">` 的 `FileList` 还是原来那批文件。用户删掉一个、再补选一个时，浏览器会把整批文件重新交给 `change` 事件，被删的那个就"复活"了。所以删除后必须用 `DataTransfer` 把剩下的文件写回 `input.files`，让界面、输入框、提交数据三者一致。

`DataTransfer` 不可用时跳过同步（提交仍用 `picked`），不影响主流程。

## 三、验收

单元测试 **88 项通过**。

浏览器验收 **12 项全通过**：

| 分组 | 项数 | 关键断言 |
| --- | --- | --- |
| 店铺页 | 4 | 只剩 1 个「发起询盘」；`.storefront-contact` 不存在且页面无该标题；简介区单列（`grid-template-columns` 只有一个值）；头部主按钮 `href` 仍指向 `rfq.html` |
| 附件删除 | 4 | 选 2 个文件各带移除按钮；删一个后剩 1 个；删掉的是被点的那条；`input.files.length` 同步为 1 |
| 不复活 | 1 | 再选一个文件后，被删的文件没有回来 |
| 提交一致 | 1 | 提交后落库的 `attachments` 只有 1 条且是保留的那条 |
| 收件箱同款 | 1 | 回复附件 2 → 1 |

回归：侧栏 17 项、入口合并 18 项、我的店铺 42 项全部 0 失败。
