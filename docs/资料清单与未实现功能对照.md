## 0. 结论：方向匹配，但范围被明显低估

**匹配的部分**：资料清单的落点，正好压在我们标为「完全未实现」的 §3.9 / §3.10 / §3.11 和「部分实现」的 §2.4 / §3.3 / §3.7 上。认证、内容、素材三块的资料项，与 M3 / M4 / M5 几乎一一对应，没有跑偏。

**不匹配的部分有四处，且都会影响排期：**

1. **优先级直接冲突**：PRD 把 3.9 认证、3.10 内容、3.11 素材列为「必做，与 P0 同优先级」；资料清单却把认证/素材放 **P1**、内容中心和批量导入放 **P2**。同一份需求基线，两套优先级。
2. **范围被低估约一倍**：83 项资料里，按代码逐项判定只有 **19 项已实现、9 项部分实现、55 项未实现（66%）**。我们的未实现清单只点名了其中 **28 项**，还有 **27 项完全没有对应条目**——集中在入驻资料（3.2）、公司介绍（3.3）、产品字段与贸易信息（2.4）。
3. **产品参数是最大缺口**：资料清单要求类目参数 **82 个字段**，当前代码只有 **34 个（缺 48 个）**；合规要求 **30 个「类目×强制项」组合**，当前只覆盖涂装的 **6 个（20%）**。我们的 M6 只写了「批量导入 / 素材引用 / 状态机」，完全没提参数与合规扩容。
4. **技术方案硬冲突**：清单允许视频 200MB、图片 10MB、PDF 10MB；原型 localStorage 上限约 5MB 且当前把图片转 base64。按清单验收，第一次上传就会写失败。

### 3.3 公司介绍（16 项）— M8 只覆盖了 4 项

已实现：中英名称、国家/城市、官网、业务类型、成立年份/员工数、中英简介、主营类目、实拍文件名。
完全缺失：**Logo 上传**（≥400×400、≤2MB）、**详细地址**、**注册资本/厂房面积**、**核心产品线关键词**、**企业视频**（30–120 秒、≤200MB）、**产能与设备清单**、**QC 流程**、**团队与核心人员**、**合作案例（脱敏）**、**参展记录**。
约束缺失：简介要求富文本、中文 300–500 字 / 英文 150–300 词、禁留电话邮箱网址二维码——当前是纯 textarea，无字数与敏感信息校验。

### 3.7 店铺装修（4 项）— 0 项实现，但清单允许延后

Banner（1920×480、≤3MB、1–3 张）、展示语（≤40 字）、主题/配色、主营类目排序。四项均无字段。清单明确标注「本期静态原型仅预留字段」，与 PRD「店铺主页必做」并不矛盾——**店铺主页页面要做，装修配置可以先只留字段与空状态**。这一点建议写进 M2 的验收口径，避免把装修当成 P0 阻塞。

### 3.9 / 3.10 / 3.11 — 匹配，补细节即可

- **认证**：M3 与清单 10 项一一对应。需补充的细节：企业资质与入驻营业执照**共用一份、不重复上传**；证书「有效期 + 到期前 30 天提醒续传」；国别准入（REACH/FDA/JIS/KC/IMDG）；荣誉与资质等级；验真方式（人工 vs 第三方）为待拍板项。
- **内容**：M4 覆盖完整。需补：封面 1200×630/≤2MB、分类标签 1–3、关联产品 ≤6、作者简介 ≤200 字、联系我们表单字段、正文英文 ≥300 词。
- **素材**：M5 覆盖完整。需补：删除前校验引用次数（避免破图）、图片 ≤10MB/视频 ≤200MB、素材引用链接由系统生成。

### 3.6 / 3.8 — 清单不采集资料，无法用于验收

清单说明页明确：**3.6 工作台只消费「完善度」与「待补项」，3.8 客户管理消费询盘与联系方式，本身不采集资料**。因此：

- M1 的 KPI 定义、待办规则、账户得分**权重与阈值**，清单没有给，仍需产品定义。
- M11 的客户分组、买家动态、排序规则，清单也没有给。
- 但清单提供了 M1 的**数据来源**：推荐项计入完善度、待补项以待办形式提醒，这与 M1 的设计一致。

## 5. 冲突与必须先拍板的问题

| # | 冲突 | 两侧说法 | 需要谁定 |

| C3 | 审核流程 | 清单每项都有「审核方式」（人工/第三方/财务）；PRD 与我们的清单明确「运营后台本期不做」 | 产品 + 运营（建议原型只做状态标识与模拟通过） |

清单自带的 6 个待拍板项，全部会卡住我们的验收口径，建议一并确认：
1. 价格是否必须公开；2. HS 编码是否对出口类目必填；3. 证书是否接第三方验真（SGS/TÜV）还是平台人工核验；4. 店铺装修是否对普通会员开放；5. 批量导入 ≤500 行的失败策略（部分成功 or 整体回滚）；6. 各环节审核 SLA。

另有一处**清单本身的数据质量问题**：说明页声明「必填=黄底、类目强制=红底」，但主表与字段表的 F 列底色实际为空，颜色规则没有落盘。若要把这张表当验收基线，需要先补条件格式，否则验收时无法快速识别强制项。

### 状态修正

| 条目 | 原判定 | 建议改为 | 理由 |

### 新增条目（建议并入现有编号，不重排）

- **M12 入驻资料与资质门槛**（3.2，补 6 项）
- **M13 公司介绍扩容**（3.3，补 10 项 + 富文本约束）
- **M14 产品字段与合规体系**（2.4，补 48 参数 + 9 贸易字段 + 合规矩阵）

- **M16 审核与有效期机制**（全局，依赖 C3 决策）

### 建议实施顺序调整

原顺序是「先定契约 → 询盘归属+工作台 → 认证+店铺 → 素材+内容」。结合资料清单的 P0 定义，建议改为：

1. **先拍 C1–C4**（优先级、存储、审核、价格），否则后面三批都要返工。
2. **第一批：M7 询盘归属 + M15 文件规范 + M12 入驻门槛**——入驻是发品前置，文件规范是所有上传页的地基。
3. **第二批：M14 产品字段与合规**——这是资料清单的 P0 核心，也是买家端筛选/详情的数据源，越晚做返工面越大。
4. **第三批：M1 工作台 + M3 认证 + M9 详情验真 + M13 公司扩容**——工作台依赖完善度，完善度依赖 M13/M14 的字段。
5. **第四批：M2 店铺主页 + M5 素材库 + M4 内容中心**——三者互相引用，适合同批；店铺装修按清单口径只留字段。
6. **第五批：M11 客户管理、M6 批量导入、M10 首页入口、收藏等打磨项**。

## 7. 一句话回答「是否匹配」

**方向和落点匹配，颗粒度和优先级不匹配。** 资料清单验证了我们对 3.9/3.10/3.11 的判断是对的，但同时暴露出：3.2 入驻、3.3 公司介绍、2.4 产品字段与合规被我们明显低估——83 项里 55 项未实现，我们只点名了 28 项；再叠加两套优先级和 localStorage 容量冲突，如果直接拿这份清单排期，会在第二批就卡住。
